## 4. Responsibility R1 — complete residual token construction

### 4.1 Representation compatibility

Use the unchanged 12-slot parser used by #58A–#58D.

Primary parser policy: `min`.

For each R1 candidate, direct clean-token parser coverage must be at least **60%**.

No glyph rewrite, codebook remapping, token splitting/merging rule, or selected subset may be chosen after any candidate real R1 association is inspected.

Coverage `<60%` yields:

`FAIL_REPRESENTATION_COMPATIBILITY`

This is a scientific failure for R1, not `INCONCLUSIVE`.

### 4.2 Complete graph only

Retain all **66 unordered slot pairs**.

Use the same `K_other`-conditional Jeffreys-smoothed Mantel-Haenszel Yule-Q base statistic and residualization family as #58C/#58D.

No historically strong edge may be promoted into a selected target.

### 4.3 Candidate-owned line-local null

Each candidate is normalized against its **own** deterministic line-local occupancy null.

Primary calibration per candidate:

- `1,000` reference nulls to define edge-wise empirical mid-rank normal residual Z;
- independent `1,000` test nulls for validation and target-comparison nulls.

The null must preserve, exactly as applicable to the candidate corpus:

- physical/generated line identity;
- line length / token count;
- line × slot occupied count;
- candidate fold/document label;
- any frozen position label used by the parser wrapper;

while destroying same-token cross-slot pairing.

Candidate seed namespaces must be disjoint and include candidate, view, fold/document, and null role.

**Frozen ZL3b/IT2a null distributions may not be reused to normalize candidate edges.**

### 4.4 Primary candidate corpus

#### A1

Use the exact historical deterministic A1 mechanism and frozen parameters.

Primary generated realization per physical-leaf fold is the **first member (`rep=0`) of the already frozen historical deterministic seed family**, provided preflight proves that this identity can be reproduced from the historical code without inventing a seed.

Combine the five primary held-out fold outputs into the pooled A1 R1 corpus. Remaining historical replicates are non-promoting sensitivities.

#### Naibbe

Use the exact Phase64B source panel and primary published respaced view.

Primary realization is **realization 0** from the already frozen Phase64B deterministic seed family for each of the four CREMMA manuscripts, provided preflight reproduces its historical R2/R3 metrics from the frozen code.

Remaining historical realizations and the raw-token view are non-promoting sensitivities.

### 4.5 Residual-existence gate

Candidate residual energy:

`E = sqrt(mean(Z_e^2))` over all 66 edges.

Reliability `W` is median complete-graph correlation between train-other-folds and held-out-fold residual graphs.

- A1 folds: five frozen physical-leaf folds.
- Naibbe folds: four frozen CREMMA manuscript folds.

R1 residual existence passes iff:

- at least four valid reliability folds exist;
- `W >= .50`;
- independent test-null familywise `p_exist_maxT <= .01`.

For familywise protection, test-null replicate `r` forms the maximum residual energy over **both prospectively selected R1 candidates** that are representation-compatible. Observed candidate E is evaluated against that maximum distribution.

### 4.6 Topology against both independent Voynich readings

Compare each candidate's complete 66-edge residual Z vector against the already frozen pooled `ALL` references:

- ZL3b #58C;
- IT2a #58D.

For each candidate/reference pair compute:

- Pearson correlation `R`;
- sign agreement out of 66.

For every candidate test-null graph, compute the same two statistics against both real references.

Familywise null replicate `r` takes the maximum over the full prospective family:

- both R1 candidates B2/B3 that pass representation compatibility;
- both frozen target readings ZL3b/IT2a.

Use separate maxT distributions for Pearson correlation and sign agreement.

A candidate topology passes iff **for both target readings**:

- `R >= .70`;
- Pearson `p_maxT <= .01`;
- sign agreement `>= 50/66`;
- sign-agreement `p_maxT <= .01`.

These effect-size gates are inherited from the already frozen #58D topology standard, not selected from B2/B3 R1 results.

### 4.7 R1 PASS

R1 passes iff all of the following pass:

1. representation compatibility;
2. residual existence;
3. reliability;
4. topology vs ZL3b;
5. topology vs IT2a.

No R2/R3/R4 success can rescue R1.

## 7. Responsibility R4 — decoder closure

R4 applies only to B2 Naibbe in the first tournament.

### 7.1 Closure target

The primary identity is:

`D(E(P)) = normalize(P)`

where `normalize(P)` is exactly the Phase64B source-side plaintext projection:

1. pinned published `clean_line()` behavior;
2. the preregistered Phase64B drop-only projection to the 23 effective supported letters;
3. published `W→UU`, `J→I`, `K→C` normalization;
4. original spaces/punctuation are **not** part of the recoverable target because the published encoder removes them before ciphering.

The test uses the exact published primary ciphertext view with `SPACE_REMOVAL_RATE=0.03`.

### 7.2 Unique recovery requirement

The pinned public decoder may emit alternatives or unresolved markers.

For primary PASS, after mechanically parsing the decoder's published ambiguity notation:

- exactly **one** fully resolved normalized plaintext letter stream must remain for every frozen source-side test message/line;
- that unique stream must equal `normalize(P)` exactly;
- `[?]`, multiple surviving plaintext streams, or a wrong stream fail that item.

Report separately, without promotion:

- fraction where truth is contained among multiple alternatives;
- unresolved-token rate;
- unique-but-wrong rate;
- raw-token/no-space-removal sensitivity if useful.

A correct plaintext merely appearing somewhere in an ambiguity set is **not** exact decoder closure.

### 7.3 Side-information firewall

Primary R4 decoder input is limited to:

- ciphertext itself;
- globally frozen public Naibbe tables/algorithm.

Forbidden:

- source plaintext length as a disambiguation key;
- RNG seed as a decoder key;
- per-token table choices;
- removed-space mask;
- source word boundaries;
- source vocabulary/list;
- any side information scaling with message length;
- any choice based on Voynich target statistics.

The stochastic encoder is **not required to reproduce the same ciphertext when re-run**. Encryption reproducibility and decoder closure are separate questions.

### 7.4 R4 PASS

R4 passes only with **100% unique exact normalized-stream recovery** on the frozen source-side audit population under the primary published 3%-space-removal view and the side-information firewall above.

A no-space-removal or raw-token sensitivity cannot promote a primary R4 failure.
