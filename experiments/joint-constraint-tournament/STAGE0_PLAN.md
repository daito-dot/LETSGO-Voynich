# Issue #68 — Stage 0 authority, replayability, and responsibility audit plan

Status: **PREREGISTERED — NO NEW CANDIDATE JOINT-SCORE TARGET AUTHORIZED**

Base main at branch creation:

`a7a0f4bf9a0b8e5b0df665761702fe8881289d15`

This plan must predate any Stage-0 audit executable and any tournament target plan/executable.

## 1. Program transition

The project has moved from local structural discovery to mechanism discrimination.

#58D established that the token-internal residual construction signature survives independent ZL3b and Takahashi/IT2a readings inside a common EVA/IVTFF framework.

Frozen #58D classification:

> `INDEPENDENT TRANSCRIPTION REPLICATES RESIDUAL TOKEN-CONSTRUCTION CORE`

The immediate research question is now:

> **Can any bounded reversible/generative mechanism jointly reproduce the strongest already-established Voynich constraints on held-out material without post-hoc repair?**

Stage 0 does **not** answer that question yet. It establishes which historical responsibilities and baseline mechanisms can be replayed fairly inside one tournament before any new joint candidate outcome is observed.

## 2. Why Stage 0 is required

The strongest responsibilities were created in different phases with different wrappers, populations and historical code paths.

A joint tournament would be scientifically invalid if it silently:

- changes S1 or H62 definitions while porting them;
- compares candidates on different held-out leaf populations;
- gives one candidate true layout/vocabulary information denied to another without accounting for it;
- labels a non-reversible generator a decoder;
- imports a historical baseline whose current-main implementation cannot reproduce its frozen result;
- builds the complexity penalty only after seeing which candidate wins.

Therefore authority/replayability must be audited before tournament scoring exists.

## 3. Stage-0 scientific firewall

Stage 0 may:

- inspect exact historical plans/reports/results/source code;
- identify metric implementations and their dependencies;
- reproduce already published/frozen historical values when exact replay is needed to verify authority;
- compare population/fold definitions;
- inventory candidate inputs/parameters/state/reversibility claims;
- derive **no new candidate joint outcome**.

Stage 0 must not:

- score a new candidate family on the combined C1/C2/C3 battery;
- tune a model using the replicated #58D graph;
- choose an edge subset based on candidate performance;
- change H62 or S1 thresholds because a candidate would otherwise fail;
- create a weighted omnibus score after observing candidate tradeoffs;
- decide complexity penalties from candidate target results.

If a historical frozen baseline is replayed, the audit must label that as `historical replay`, not a new scientific reveal.

## 4. Responsibilities to audit

### R1 — cross-reading residual token construction

Authoritative science:

- #58C residual existence / within-ZL structure;
- #58D independent-reading complete-graph replication.

Stage 0 must identify:

- exact frozen source/result files and SHA authorities;
- exact 66-edge ordering;
- parser/population/folds used;
- a candidate-output scoring interface that can compare a generated/transformed held-out output against the replicated token-construction responsibility **without selecting individual edges after candidate inspection**;
- whether the tournament should use full residual vector, sign vector, energy + topology, or a prior-derived fixed summary.

Stage 0 must not select the representation based on candidate performance.

### R2 — H62 short-range near-family recurrence geometry

Stage 0 must identify:

- exact frozen H62-P1 authority and result files;
- exact held-out leaf folds;
- exact profile components and distance definition;
- exact historical N0/C0/A1 comparisons;
- whether the current-main code can reproduce the frozen score from the frozen source without modification;
- candidate-output interface required to compute H62 from arbitrary generated/transformed paragraphs.

### R3 — signed S1 paragraph-entry specialization

Stage 0 must identify:

- exact frozen S1 authority and feature/contrast definition;
- training-side direction/standardization steps;
- held-out projection definition;
- exact physical-leaf/paragraph eligibility rules;
- known historical controls/candidates and retained failures;
- candidate-output interface required to compute signed S1 without target leakage.

S1 must remain an independent hard responsibility in the tournament; it may not be averaged away.

### R4 — reversibility / recoverability

For each historical or proposed candidate family Stage 0 must record:

- `surface generator only`, `reversible transform / decoder candidate`, or `control / null`;
- whether exact reversal is mathematically defined;
- what side information the decoder requires;
- whether historical code contains an explicit decode/re-encode path;
- whether a held-out exact closure test is possible.

Do not infer reversibility merely from the family name.

### R5 — complexity / access accounting

Stage 0 must inventory a candidate-independent accounting schema covering at least:

- free scalar parameters;
- learned symbol/digraph/substitution tables and their cardinality;
- learned token vocabulary or empirical token inventory;
- state-space size / memory order;
- section/paragraph/line-conditioned parameters;
- held-out layout/token-count information supplied;
- external source corpus information supplied;
- candidate-specific preprocessing/mapping;
- decoder side information;
- per-held-out-item adaptation, which should normally be forbidden.

Stage 0 must propose a fixed complexity representation before tournament outcomes. It may recommend hard ceilings, a description-length proxy, or both, but the final numerical rule belongs in the later target plan.

## 5. Baseline/candidate replay audit set

Stage 0 should audit at least these historically relevant anchors if they are present and replayable on current main:

### B0 — source-native / N0-type control

Purpose: establishes what untransformed structured source text does on the reused responsibilities where meaningful.

### B1 — fixed C0-type reversible recoding

Purpose: bounded low-complexity reversible-transform anchor.

Stage 0 must determine the exact historical C0 variant(s), whether reversal is explicit, and whether the same variant is appropriate across all responsibilities.

### B2 — strongest fair prior C-family comparator

Candidate examples may include the published/frozen C1/Naibbe or other accepted strongest historical C-family comparator, but Stage 0 must identify the current authoritative one rather than assuming a name from chat.

Purpose: give cipher/shorthand-like architecture a serious replayable comparator.

### B3 — A1/A1-R1

Role: **surface-generation comparator**, not decoder unless explicit reversibility exists.

Stage 0 must inventory its empirical dependencies, including training vocabulary/morphology/layout information and historical parameter selection, so its apparent fit is not compared to reversible transforms as if information access were equal.

## 6. Population/fold compatibility audit

Stage 0 must produce a matrix for R1/R2/R3 showing:

- transcription/source authority;
- physical leaves available;
- five-fold definitions;
- paragraph/line eligibility rules;
- token population sizes;
- whether exact same held-out folds can be reused;
- what population intersection would be required for a common tournament;
- what scientific information would be lost by forcing an intersection.

Preferred outcome:

> one common physical-leaf fold authority with responsibility-specific eligibility applied inside each held-out fold.

Do **not** force all responsibilities onto an artificially tiny identical token subset if leaf-level held-out separation is sufficient and historical definitions can remain intact.

If fold authorities differ materially, freeze a principled harmonization rule in a later target plan before any new candidate score.

## 7. Candidate-output contract audit

Stage 0 must define the minimal data structure a future candidate must emit for each held-out item so R1/R2/R3 can be computed consistently.

At minimum determine whether the contract needs:

- physical leaf/page identity;
- paragraph boundaries;
- physical line boundaries;
- token boundaries;
- token strings in a common scoring alphabet;
- source plaintext identity for reversible candidates;
- encoder state/side-information record;
- exact target layout supplied vs generated flag.

The scoring contract must not require model-specific hidden access.

## 8. Historical replay acceptance rules

A reused responsibility or baseline is `REPLAY_READY` iff:

1. exact frozen authority can be identified;
2. current-main code or a provenance-preserving wrapper reproduces the frozen result within exact/numerically explained tolerance;
3. no scientific definition changes are required;
4. its inputs/access are explicit;
5. a candidate-output interface can invoke the same metric prospectively.

Otherwise classify:

- `REPLAYABLE_WITH_FROZEN_WRAPPER` — historical code needs an isolated compatibility wrapper but scientific definition remains unchanged;
- `NOT_TOURNAMENT_READY` — authority/inputs/metric cannot be safely reproduced;
- `HISTORICAL_ONLY` — useful contextual result but unsuitable as a common prospective responsibility.

Do not silently repair a `NOT_TOURNAMENT_READY` baseline into the tournament.

## 10. Stage-0 completion classes

### `JOINT TOURNAMENT AUTHORITY READY`

Use only if R1, R2 and R3 are all replay-ready or replayable with frozen wrappers, a common held-out leaf framework is feasible, and at least one reversible-transform baseline plus one structural-generator comparator are adequately characterized.

### `JOINT TOURNAMENT REQUIRES AUTHORITY REPAIR`

Use if the core responsibilities are scientifically usable but one or more need provenance-preserving wrappers/archival repair before target planning.

### `JOINT TOURNAMENT DESIGN BLOCKED`

Use if R1/R2/R3 cannot be combined without changing a scientific definition or introducing target-dependent harmonization.

No target plan should be written until Stage 0 reaches READY or a separately documented authority-repair path is completed.
