## H68-R4 — reversible closure

Status: **PREREGISTERED / SOURCE-SIDE TEST ONLY**

For Naibbe, the correct question is not whether stochastic encryption can regenerate the identical ciphertext.

The primary closure question is:

> Does the pinned public decoder recover exactly one normalized plaintext letter stream and is it exactly the frozen normalized source stream for every primary source-side item, using only ciphertext + global public tables/algorithm?

Original source spacing/punctuation and the pre-encryption W/J/K distinctions are not recoverable targets because the published encoder discards/normalizes them.

Truth merely appearing among multiple decoder alternatives does not count as exact closure.

## Interpretation boundary

A future joint-competitive result would identify a mechanism worth deeper inverse testing. It would not itself provide a plaintext, historical identification, semantic proof, or decipherment.

A full failure would also not prove “meaningless text”; it would reject only the prospectively tested bounded candidates under the current replicated constraint set.
